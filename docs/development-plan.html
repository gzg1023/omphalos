Omphalos 开发计划与进度

修订：2026-11-09 · 先验证，再交付 MVP，随后按需求迭代

项目定位

本地优先的 Agent 控制台，连接 Claude Code、Codex 等执行器，统一管理任务、运行记录、人工审批与产出。Omphalos 为公开开源项目。

第一版聚焦

单用户、本机运行、Web 任务管理、一个 Runner、日志与产出、已验证的执行审批。

后续逐步扩展

飞书 → Codex → 记忆与助手 → 工作流 → 插件与多渠道。后续阶段是方向，可根据反馈调整。

架构与工程约定

入口（Web / 后续飞书） → 应用服务（任务、队列、策略） → Runner 适配层 → 本地执行器。SQLite 保存状态和事件，SSE 推送运行进展。

核心对象

Task 表达目标；Run 表达一次执行；Approval 绑定具体操作或版本；Artifact 保存产出。重试与返工创建新 Run。

能力与安全边界

权限以执行器可落实的机制为准；worktree 隔离改动，子进程管理生命周期，两者都不是沙箱。插件与公网部署另行设计权限边界。

状态与审批规则

Run：queued → running ↔ waiting_approval → succeeded / failed / cancelled；执行中断标记 interrupted。cancel_requested 是中止请求，收到停止证据后才确认 cancelled。

执行权限审批、工作流审批、产出审核分别建模。审批绑定 run、操作或产出版本、身份和有效期；重复操作幂等。恢复会话不等于重试，外部副作用不能自动重放。

开发节奏与进度

每次约 2 小时作为工作块，任务可跨多个工作块。验收通过才标记完成；阻塞任务先记录原因。进度按任务计数，不代表工时。
